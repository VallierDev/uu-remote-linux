可手动选择视频编码器和 codec，auto 改为后台探测；Wayland 屏幕保活失败不再中断画面；viewer 新增安全输入 `type`。/ Encoder and codec settings, background auto probe, display-wake failures no longer stop video, and a secure `type` command in the viewer.

### 新增 / Added
- **编码器与 codec 设置**（#85 第①②步，#92、#93，感谢 @ferstar）：`uuremote-server set-encoder auto|cpu|vaapi|nvenc`、
  `uuremote-server set-codec auto|h264|h265` 写入 `~/.config/uuremote/host_settings.json`，优先级高于 `UU_VIDEO_ENCODER` / `UU_VIDEO_CODEC`，
  下次建立桌面连接时生效；`doctor` 显示来源和最终 codec。auto 在启动时后台探测（每个候选编码一帧合成画面，限时 3 秒，不挡第一路出图）：
  有 NVIDIA 时 NVENC → CPU，没有 NVIDIA 时直接用 CPU 不探测。NVENC 探测失败只缓存 10 分钟，之后的桌面连接会在后台重探；
  NVIDIA 驱动或设备中途出现/消失也会重探。显式指定编码器时不探测。VAAPI 要等 #33 解决后才进入 auto。
- **viewer 安全输入 `uuremote-viewer type`**（#70，感谢 @212duo）：向已打开的桌面会话注入键盘（锁屏 PIN / 密码），文本不进 argv，
  日志只记长度；按 US QWERTY 键位映射。本机 IPC 用私有目录和对端 uid 校验。
- `set-encoder` / `set-codec` write the video settings to `host_settings.json`; auto now probes NVENC then CPU in the background
  (CPU only without NVIDIA, NVENC failures retried after 10 minutes). The viewer gains `type`, a secure key-injection command that
  reuses the open desktop session.

### 修复 / Fixed
- **Wayland 运行中屏幕保活失败会停掉视频**（#94、#95，感谢 @AYssu）：启动时和每 30 秒的屏幕保活改为尽力而为，失败只记警告、下轮重试，
  画面继续发送；采集、编码、发送错误仍按原逻辑处理。
- A failed display wake at stream start or during the 30-second refresh is logged and retried instead of ending the video.

### 验证范围 / Validation
单元测试与 CI（x86_64、arm64、Wayland、inproc-av、viewer）通过；以上改动尚未在报告者现场或 NVIDIA 机器上实机验收。
