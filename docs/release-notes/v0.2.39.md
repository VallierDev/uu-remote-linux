Linux 控制端像官方控制端一样请求桌面视频轨道，修复第二个会话永久黑屏。/ The Linux viewer now requests the desktop video track like the official viewer, fixing a permanently black second session.

### 修复 / Fixed
- **第二个会话黑屏（#124，感谢 @shao-zhijie 的码流取证）**：被控端已在给别的控制端推流时，Linux 控制端只会接上那条流的中段，没有 SPS/PPS/IDR，永远无法解码；官方主机也不响应 RTCP PLI。官方 iPhone 控制端在 CONTROL 通道打开后会立即发 RPC 15 `SendVideoTrackReq`（无字段）；Linux 控制端现在桌面会话里也发这一条。
  Desktop sessions now send RpcRequest case 15 `SendVideoTrackReq` (no fields) right after CONTROL opens, as the official iPhone viewer does, so the host starts a track for this session instead of the viewer joining another session's stream mid-GOP.

### 验证范围 / Validation
单元测试与 CI；官方 iPhone 控制端发送该 RPC 的行为来自本项目主机日志（`response_field=11 value=None`）。与官方 macOS 主机的第二会话场景尚待报告者实测。
