观看模式「批注」可用（X11），空闲主机 CPU 占用下降，防窥重启后可恢复输入设备，Portal 授权不再因中途失败丢失。/ Watch-mode annotation works on X11, idle hosts use less CPU, privacy restore survives a reboot, and rotated Portal consent is no longer lost.

### 新增 / Added
- **观看模式批注（#174，感谢 @Chr0mium24）**：主机应答官方查看端的批注 RPC（draw_req），笔迹画在可穿透点击的 X11 覆盖窗口上（需要合成器），分辨率变化时覆盖层随之重建。此前查看端报「批注开启失败（9998）」。仅 X11；Wayland、移动端查看端和多显示器未实测。
  The host answers the official viewer's annotation RPC (draw_req) and draws strokes on a click-through X11 overlay (needs a compositor), rebuilt when the resolution changes. X11 only; Wayland, mobile viewers and multiple monitors untested.

### 修复 / Fixed
- **空闲主机 CPU（#172，感谢 @ferstar）**：指针工作线程在没有指针/滚轮/按键/触控手势时挂起，不再以 4 ms 周期空转（无查看端时约 3% CPU）。/ The pointer worker parks while no pointer, scroll, button or gesture work is pending, instead of ticking every 4 ms (~3% CPU idle).
- **防窥重启后恢复输入设备（#173，感谢 @RiverOnVenus）**：KDE 防窥记录按设备名称/产品/厂商匹配，重启后 eventN 编号变化也能重新启用被禁用的设备；已不存在的设备跳过，不再让后续防窥切换一直失败。/ KDE privacy records match devices by name/product/vendor, so a renumbered device is re-enabled after a reboot; missing devices are skipped.
- **Portal 授权先持久化（#175，感谢 @jinpeng2700-tech）**：Portal 返回轮换后的一次性 restore token 时立即保存，不再等首帧；采集失败或取消时不会丢失授权、下次重新弹窗。/ Rotated single-use Portal restore tokens are saved as soon as Portal returns them, so a failed or cancelled capture no longer forces a new consent prompt.
