`UU_USE_PROXY=1` 时经 TCP/TLS（可走 HTTP 代理）连接 TURN 中继，供 UDP 到不了中继服务器的主机使用。/ With `UU_USE_PROXY=1`, TURN relays are also reached over TCP/TLS (optionally through the HTTP proxy) for hosts whose UDP cannot reach the relay servers.

### 新增 / Added
- **TURN over TCP/TLS**：云端在强制中继的会话里也会下发 `turns:<IP>:<端口>?transport=tcp`，原来使用的 webrtc-ice 只支持 UDP 中继，UDP 被限制、只能经 HTTP 代理出网的主机因此拿不到任何中继候选，控制端一直"正在尝试重连"。现在开启 `UU_USE_PROXY=1` 后，主机会经 `HTTPS_PROXY`/`ALL_PROXY` 中的无认证 `http://` 代理（没有则直连）建立 TCP/TLS 中继连接。TURN 证书按 CA 链校验，仅在云端下发的地址为 IP 时容忍名称不匹配；媒体仍由 DTLS-SRTP 端到端加密。未开启时只用 UDP 中继，行为不变（`vendor/webrtc-ice/PATCHES.md`）。
  With `UU_USE_PROXY=1` the host also opens TURN relays over TCP/TLS through the unauthenticated `http://` proxy (or directly), chain-verifying certificates and tolerating a name mismatch only for IP TURN URLs. The default stays UDP-only.
