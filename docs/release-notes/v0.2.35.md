信令可走 HTTP 代理、二维码登录错误分类、重复主机实例诊断，以及 Wayland 手机端文字输入兜底。/ Signaling through an opt-in HTTP proxy, clearer QR login errors, duplicate-host diagnostics, and a Wayland fallback for mobile text input.

### 新增 / Added
- **信令遵循 `UU_USE_PROXY=1`（#123）**：主机和 Linux 控制端的 WebSocket 信令改用与 REST 接口相同的 HTTP 客户端，开启 `UU_USE_PROXY=1` 后也走环境里的 HTTP/HTTPS 代理（不支持 SOCKS；选中的代理失败不会改为直连；不跟随重定向）。不代理 ICE/WebRTC 媒体。默认（不开代理）行为不变。
  Host and viewer signaling now use the same HTTP client as the REST API, so `UU_USE_PROXY=1` applies to signaling too (HTTP/HTTPS proxies only, no direct fallback, no redirects). Media is not proxied; the default is unchanged.
- **Wayland/Portal 手机端文字输入兜底（#119，感谢 @shofukantkts）**：没有空闲键码的合成器和 Portal 后端上，手机端输入的文字经剪贴板 + Shift+Insert 粘贴；`UU_WAYLAND_TEXT=0` 可关闭。
  Mobile text input on Portal and compositors without spare keycodes is pasted via the clipboard and Shift+Insert; `UU_WAYLAND_TEXT=0` disables it.

### 修复 / Fixed
- **二维码登录错误分类（#121）**：状态查询失败不再一律提示「网络超时」，区分超时、连接失败、响应异常与二维码过期；诊断只含阶段、类别、耗时和状态码，不输出票据、URL 或服务器内容。
  QR polling failures are no longer all reported as a network timeout; timeouts, connection failures, bad responses and expiry are distinguished, with diagnostics that never include tickets, URLs or server content.
- **重复主机实例（#122）**：同一身份的两个主机实例（拷贝了 `config.json`，或残留的旧手动实例）会互相把对方踢出房间，表现为控制端一连就断。`doctor` 现在能数到重新执行后进程名为 `exe` 的实例并给出提示；README 说明不要在机器之间拷贝 `config.json`；日志会记录无 peer id 的 leave 事件结构（仅键名/类型/长度）。
  Two host instances sharing one identity kick each other out of the room. `doctor` now counts re-executed instances and warns about extras, the README explains not to copy `config.json` between machines, and leave events without a peer id log their shape (keys/types/lengths only).

### 验证范围 / Validation
单元测试与 CI。#123 在真实 Linux X11 主机上实测不开代理时信令与 iPhone 桌面连接正常；经真实代理的信令尚未实测。#122 的修复在报告环境实机验证。
