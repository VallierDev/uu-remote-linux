官方控制端能选「真彩」(4:4:4) 了；自行编译的 `inproc-av` 新增进程内 NVENC 与 AMD/Intel VAAPI。/ The official viewer can select true color (4:4:4); self-built `inproc-av` gains in-process NVENC and VAAPI.

### 修复 / Fixed
- **官方控制端里「真彩」不可选或打开后马上被切回**（#77、#79）：设备能力里 HEVC/4:4:4 等格式的宽高原来填的是 0x0，官方控制端会把这样的条目当作不支持。现在每种格式都带上最大尺寸 3840x2160。
  已实机验收：官方 Mac 控制端连 X11 + NVIDIA 主机，打开真彩后切到 HEVC 4:4:4，持续 30 秒以上没有被切回，也没有请求关键帧（PLI）。
- The device capability listed HEVC/4:4:4 formats as 0x0, which the official viewer treats as unsupported; each format now
  carries its maximum size. Verified with the official Mac viewer: true color stays on (HEVC 4:4:4) for 30+ s, no PLI.

### 新增（需自行编译，预编译包不受影响）/ Added (self-built only; release packages unchanged)
- `--features inproc-av`（仅 X11）：
  - **NVENC 进程内编码**（#75、#77，感谢 @ferstar）：直接读取 XShm，支持 4:4:4，不再经过 FFmpeg 进程；失败时依次回退到 FFmpeg 的 NVENC 管线、CPU。我方 NVIDIA 机器未单独验收这条进程内路径。
  - **VAAPI 进程内编码**（#80、#81，感谢 @ferstar）：通过 DRI3 DMA-BUF 零拷贝取屏（没有 DRI3 时改用 XShm 上传），经 VPP 转成 NV12 后送入硬件编码，支持 H.264 和 H.265。贡献者已在 AMD HawkPoint、Cezanne 上用官方 Mac 控制端实机验收；Intel 与 4K 尚未验证。需设置 `UU_VIDEO_ENCODER=vaapi`。
  - libcuda、libva 都在运行时加载；编译所需的头文件见 README。
- In-process NVENC (XShm, 4:4:4) and VAAPI (DRI3 DMA-BUF zero copy, H.264/H.265) under `--features inproc-av` on X11,
  each falling back to the FFmpeg process pipeline. VAAPI accepted by the contributor on AMD HawkPoint/Cezanne; Intel and 4K untested.
