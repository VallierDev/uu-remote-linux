功能版：KDE/GNOME Portal 主机可选注册调用方 app id，便于 KDE 预授权（锁屏冷连接）。/ Feature release: Portal hosts can opt in to registering a caller app id, enabling KDE pre-authorization (cold connections while locked).

### 新增 / Added
- **可选 `UU_PORTAL_APP_ID`（#266）**：xdg-desktop-portal 只从 `app-<id>.service` 单元推导 app id，默认的 systemd 用户服务得到空 id，KDE 的 `kde-authorized` 预授权无法匹配。设置该变量后，主机在首次 Portal 调用前通过 `org.freedesktop.host.portal.Registry`（xdg-desktop-portal ≥ 1.19）注册该 id；旧版 Portal 或注册失败时忽略。默认关闭：恢复授权按 app id 保存，切换 id 会使已保存的授权失效一次。README 补充了锁屏冷连接的前提和做法。/ xdg-desktop-portal derives an app id only from `app-<id>.service` units, so the default systemd user service gets an empty id and KDE `kde-authorized` grants cannot match it. When set, the host registers the id via `org.freedesktop.host.portal.Registry` (xdg-desktop-portal ≥ 1.19) before the first Portal call; older portals or failures are ignored. Off by default: restore grants are keyed by app id, so switching ids invalidates saved consent once. README documents the locked cold-connection prerequisites.
