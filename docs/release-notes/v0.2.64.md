### 修复 / Fixed
- **高基础 RTT 链路降码率后不再停在低档（#259）**：自 v0.2.60 起码率恢复要求 RTT < 150 ms，跨境等基础 RTT 较高的链路一次丢包降档后即使零丢包也无法回升。现在两个 RTT 阈值都改为同时允许高出本次会话最低 RTT 一段排队余量（恢复 100 ms、拥塞 250 ms），低 RTT 链路行为不变。/ Since v0.2.60 the cap only climbed back below a 150 ms round trip, so a long path stayed at the floor after one loss burst even with zero loss. Both RTT knees now also allow a queueing margin above the session's lowest round trip (100 ms to recover, 250 ms for congestion); short paths behave as before.

### 新增 / Added
- **viewer 强制中继（#247）**：`UU_VIEWER_FORCE_RELAY=1` 时优先使用云端下发的 TURN 中继而非直连候选；默认仍跟随云端，云端未提供 TURN 时回落并记一行警告。/ `UU_VIEWER_FORCE_RELAY=1` prefers the cloud TURN relay over a direct candidate; the default still follows the cloud, and without a TURN server it falls back with a warning.
