修复 X11 共享内存被拒时主机直接退出，以及 Linux 控制端加入已有会话时可能永久黑屏。/ Fixes the host exiting when X11 refuses shared memory, and a possible black screen when the Linux viewer joins a host that already streams to another session.

### 修复 / Fixed
- **X11 MIT-SHM 被拒时直接退出**：X 服务器无法访问本程序的共享内存段时（例如 X 服务器在另一个容器里），`XShmAttach` 返回 BadAccess，Xlib 默认错误处理直接结束了进程，原有的 `XGetImage` 退路没有机会执行。现在捕获该错误并改用 `XGetImage` 抓屏。
  When `XShmAttach` is refused (BadAccess, e.g. an X server in another container), the host now falls back to `XGetImage` instead of being terminated by Xlib's default error handler.
- **控制端加入已有会话时黑屏（#124，感谢 @shao-zhijie）**：Linux 控制端过去只在丢包或解码出错时请求关键帧；加入一条已在推流的干净 H.264 流时永远等不到 IDR。现在首帧显示前每 30 个访问单元请求一次关键帧（PLI），300 个仍无画面时日志给出提示。
  The Linux viewer now requests key frames (PLI) every 30 access units until the first frame is shown, and logs a warning after 300.

### 验证范围 / Validation
单元测试与 CI。共享内存退路尚待在报告环境实机确认；#124 中官方 Mac 主机是否响应 PLI 尚未实测。
